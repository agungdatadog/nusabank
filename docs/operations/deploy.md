# Deploy

Everything lives in GCP project `datadog-ese-sandbox`, region `asia-southeast2`.
The project is shared: every GCP object is named `indowebinar-*`.

Prerequisites: `gcloud auth login && gcloud auth application-default login`,
`gcloud config set project datadog-ese-sandbox`, Terraform ≥ 1.12, kubectl, helm.

## Order

Each layer needs the previous one. Always review the plan before applying.

| # | Layer | Command | Creates |
|---|-------|---------|---------|
| 1 | `terraform/infra` | `terraform -chdir=terraform/infra plan -out=infra.tfplan` → `apply infra.tfplan` | VPC, NAT, GKE, 3× Cloud SQL, Artifact Registry, generated passwords in Secret Manager, Workload Identity GSA |
| 2 | `terraform/k8s` | `terraform -chdir=terraform/k8s plan -out=k8s.tfplan` → `apply k8s.tfplan` | Namespaces, Datadog Operator, External Secrets, Strimzi, `external-secrets` KSA |
| 3 | `k8s/platform` | `kubectl apply -k k8s/platform` | Secret sync, Kafka + topics, MongoDB, Redis, DBM bootstrap jobs, MongoDB users (`mongo-bootstrap`) |
| 4 | `k8s/agent` | `kubectl apply -k k8s/agent` | DatadogAgent (APM, logs, CNM, USM, DBM cluster checks, Admission Controller) |
| 5 | `k8s/services/*` | `kubectl apply -k k8s/services/<service>` | partner-mock, auth, account, ledger-worker, payment, loan, biller, rewards, chat, ai-agent, admin, frontend, load-generator |
| 6 | `k8s/ingress` | `kubectl apply -k k8s/ingress` | Public origin: SPA at `/`, APIs under `/api/*`, managed certificate |

Cluster credentials: `gcloud container clusters get-credentials indowebinar-gke --region asia-southeast2`.

Images are built by Cloud Build with the repo root as context; tags are immutable, so
bump the version for every build. Gate the deploy on the build's exit code:

```bash
gcloud builds submit . --region=asia-southeast2 --config=tools/build/cloudbuild.yaml \
  --substitutions=_SERVICE=biller-service,_VERSION=0.1.1 > build.log 2>&1 \
  && kubectl apply -k k8s/services/biller-service
```

Exceptions — frontend, partner-mock and payment-service use their own folder as context:
`gcloud builds submit services/<service> --region=asia-southeast2 --tag …/<service>:<ver>`.

A new `/api/<prefix>` needs its Service (with the NEG annotation) running before the
Ingress path is added; the load balancer takes a few minutes to route it.

Steps 3–4 are separate from Terraform because their custom resources need the CRDs
that step 2 installs. Dry-run them first: `kubectl apply -k <dir> --dry-run=server`.

## Secrets

Values live only in Secret Manager and reach the cluster via External Secrets.

| Secret | Source |
|--------|--------|
| `indowebinar-dd-api-key`, `-dd-app-key`, `-anthropic-api-key`, `-rum-*`, `-jwt-secret` | Created by hand |
| `indowebinar-db-<service>-password`, `-db-<instance>-datadog-password`, `-db-<instance>-admin-password`, `-mongodb-root-password`, `-redis-password` | Generated by `terraform/infra` |

Rotate a hand-made secret without pasting it anywhere:

```bash
printf '%s' 'NEW_VALUE' | gcloud secrets versions add indowebinar-dd-app-key --data-file=-
```

External Secrets picks it up within an hour; force it with
`kubectl annotate externalsecret -n datadog datadog-secret force-sync=$(date +%s) --overwrite`.

## DBM bootstrap

`k8s/platform/dbm-bootstrap.yaml` grants the `datadog` user what DBM needs and is
idempotent. Re-run it after adding a database:

```bash
kubectl delete job -n nusabank -l app=dbm-bootstrap
kubectl apply -k k8s/platform
```

MongoDB (in-cluster) has its own job, `k8s/platform/mongo-bootstrap.yaml`: the `chat` and
`datadog` users plus query stats sampling, set at runtime — re-run it after MongoDB restarts.

Gotcha: Cloud SQL MySQL users created through the API have host `''`, not `'%'` —
grants must target `'datadog'@''`.

Verify checks:

```bash
P=$(kubectl get pods -n datadog -l agent.datadoghq.com/component=cluster-checks-runner -o name | head -1)
kubectl exec -n datadog $P -- agent status | grep -E "Instance ID: (postgres|mysql)"
```

## ai-agent cost control

ai-agent calls Claude (`ANTHROPIC_MODEL`, Haiku by default) and spends tokens on every turn.
chat-service decides per session: with `CHAT_RESPONDER=agent`, browser sessions always use
ai-agent, and `LOADGEN_AGENT_SHARE` (0–1) sets the share of load-generator chats that do.
`0` keeps synthetic chats on the built-in FAQ (no token spend); token usage per model is
visible in LLM Observability (`ml_app:nusabank-assistant`).

## Back office

`/ops` is the operator console (admin-service). Operators `ops.rina`, `ops.bayu`, `ops.dewi`
share the password in Secret Manager `indowebinar-demo-operator-password`. Only transfers that
FAILED with `RAIL_UNAVAILABLE` can be retried; every action lands in the audit log.

## Upgrades and tracer injection

GKE node and minor upgrades are excluded until 2026-12-31 (`terraform/infra/gke.tf`): every node
upgrade reschedules all pods, and a pod created before the Datadog admission webhook is back runs
without the tracer. `k8s/platform/ssi-guard.yaml` (CronJob, every 5 min) recreates such pods, one
per service per run and only while another replica is Ready. Its log line `ssi guard run` reports
`untraced`; anything above 0 for more than one run needs a look.

## Safety

- `deletion_protection` is on for the cluster and all Cloud SQL instances.
  Traffic history is the scarcest resource — never destroy to "rebuild cleanly".
- IAM is additive (`*_iam_member`) only; never manage the shared project's policy.
